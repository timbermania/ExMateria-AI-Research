# Screen Effect Gradient System

During spell effects FFT dims and colors the screen by drawing the background as a Gouraud-shaded fullscreen quad (GP0 0x2C/0x38) whose four vertex colors are driven by the screen track — Track 3 of the timeline color-track system. The track holds 33 keyframes (int16 time, interleaved start/end RGB, control byte); each keyframe either fades linearly from start to end RGB, or tints via one of 11 blend modes in the applier at 0x80090258, then ramps linearly to the computed target. All gradient state lives in fixed RAM blocks in 16.16 fixed point (primary 0x800a1b18, secondary 0x800a1b7c, current 0x800f5b40), and screen-background interpolation is pure linear per-frame delta accumulation — the dither-curve table at 0x800956e4 belongs to the palette color tracks (unit tinting), not to the screen background. A 2026-08 E005/Raise pass closed the open "V-shape" thread: the dim→recover→re-dim V on the background gradient is authored (framebuffer-confirmed on the PSX) and Godot reproduces it continuously with no seam pop; the combat arming path is `FUN_80090258` on this same gradient block (the subtractive `screen_tint_apply` quad is scenario-only), and `ScreenSubsystem` has since migrated onto the unified `ColorStack`/`ColorRecipe` model, folding TOP+BOTTOM through one continuous op stream. A 2026-07-14 E173/Night-Sword dual-grounding pass (Ghidra static trace + PCSX-Redux `nightsword`/`savestate9` captures) confirmed the static verdicts live and fixed the nomenclature: ctrl bit-7 selects **Blend** (set: one of 11 color-math modes, `mode = ctrl & 0x7F`, shared param = signed `start` byte ×2, `end` ignored) or **Gradient** (clear: absolute write of independent top/bottom stops, unsigned 0–255 — a real write, never a no-op; the screen lane has no null/hold entry, unlike the palette lane); it pinned the applied window to `0..max_keyframe−2` (PSX drops the tail keyframes), the Blend param to the signed start byte doubled (byte-exact vs `savestate9`), and the packed-byte base gradient at `0x800a1b48` (top/bottom triples) as the baseline the base-reading modes fold over — the Godot `import-godot-game` branch matches all of it (Gradient op + narrow bound, then the `double_param` thread, both TDD). A 2026-08-17 static re-derivation re-confirmed the model from the stepper level — the bit-7 test and the snap-vs-arm semantics live in `advance_screen_color_track @0x801A45C8` / `for_each_phase_timeline_tick @0x801A3408` and `screen_gradient_color_setter @0x80090048`, both paths tween the same gradient block under the shared vblank DDA ticker, and the same `< max_keyframe − 1` guard holds on every palette track too — and widened the corpus census (in-window black Gradients: E164/E170/E171/E173; out-of-window neutral recoveries: E006/E027/E156), while pinning `{3E}` Color Screen as a distinct mechanism sharing only the gradient block; mainline `ScreenSubsystem` still lacks the Gradient write, the narrow bound, and the ×2 param — carried only by `import-godot-game` / `feature/effect-studio-authoring`.
