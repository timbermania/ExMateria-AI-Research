# Map Tint

The "Affected Units" palette track (Track 0) is the map's only colour channel: a live Raise/E005 capture shows only field CLUT banks 0/3/4 of the dynamic strip moving, the stored base palette is never committed, and `caster`/`target` route to unit palettes, never the field strip. A 2026-08 Holy/E015 framebuffer pass settled the open question: the WHOLE visible map/terrain/sky/unit tint is the 5-bit field CLUT (bank 0 of `dynamic_clut_view_strip`, ramping to `0x7FFF` at the flood peak, byte-matched at VRAM (0,494)) — a third 8-bit additive applier `FUN_80090dec @0x80090DEC` (×8, outdoor-gated) does exist in code and stamps the untextured border-polygon class via `d2b4/d568`, but renders nothing visible in the Holy scene (pixel-identical A/B), and the CLUT rewrite lands before per-face Gouraud lighting so terrain shadows survive a dim. Godot delivers the channel as one continuous `ColorStack` fold across all started phases (`PaletteSubsystem.build_stream` → `MapTintOverlay`), with no phase-boundary pop; PSX terrain steps 5-bit per-pixel and its smoothness is spatial + temporal dither, not higher bit-depth. The Holy "clicking" was a Godot `ColorStack` `Layer.progress_at` restore-resurrection bug (a later mode-8 restore resurrected the flood layer to full white from its start frame), fixed by gating the restoring branch on `now >= restore_start` (regression-tested). Script opcodes 0x75/0x76 can disable/re-enable the map tint via bit 2 of effect_render_flags.
