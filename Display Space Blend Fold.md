# Display Space Blend Fold

The Godot reimplementation reproduces the PSX semi-transparent blend in the combat display space with a depth-ordered fold: prims are OT-depth ordered, grouped into runs of one blend direction (adjacent same-direction runs collapsed), and each run is a single hardware-blended instanced draw into a clamping UNORM scratch — so the attachment's saturation *is* the PSX per-step clamp, with non-associativity biting only at add↔sub run boundaries (byte-exact vs the per-prim fold over 200k trials). Every routed material is a single-sample sprite re-sampled in the fold's fragment, and the fold's vertex stage is one shared GPU billboard+OT-depth+PAR stretch that the stager feeds only corner offsets + world origin. The unit's complex opaque fragment (~60 samples + 30 ray-casts/pixel) is not routed; the one blend prim a unit does become — the scenario-6 dead-unit fade, ABR mode 1 additive with alpha=coverage — needs only a clamping target, not the ordered fold. A 2026-07-21 feasibility study (`COMPOSITOR_CAPTURE_OUTPUT_FEASIBILITY.md`) closed the "capture the material's own shaded output into the compositor" path as engine-blocked in stock Godot 4.6 and unnecessary, leaving the per-material fold-GLSL route (Paths 1+2) as the sole vehicle. As of #228 Phase 3 (2026-07-29) the raw-RD module behind this fold (`CombatDisplaySpaceComposite` + `CombatCompositeDriver`) has been retired and the fold now runs in `FoldSurface` + `EngineFoldCompositor` on a Forward+ 4.8 engine fork, with the essential couplings (ADR-0009 reversed-Z occlusion, ADR-0040 24-float packing, the `A2B10G10R10_UNORM` display-space clamp, the required LINEAR tonemap) carried over. MIX (mode 0) never collapses — it rescales dst and is non-commutative even with itself — and ordering matters only between screen-overlapping prims; the fold-order key is the CPU view-space-Z `ot_order_z` (decoupled from the GPU `ot_depth` occlusion value — the shared reversed-Z mirror was the bug), bucketed at the fixed PSX-calibrated width (0.19 world-u per bucket) with per-frame span normalization, and probe-verified on DEMI (E046, 2026-07-20): the full effect spans 9–16 of our buckets vs ~7–18 on PSX, the black+white overlap cloud 1–3 vs ~1–2 so the DEMI2 age tie-break still governs it. A 2026-07-19 spike closed the last open architectural risk of the ADR-0040 integration: a `CompositorEffect` can draw instanced straight from a `MultiMesh`'s RD instance buffer (`multimesh_get_buffer_rd_rid` + storage buffer + `gl_InstanceIndex`), with the buffer's 20-floats/instance layout confirmed at runtime. A 2026-07-21 universal-routing scoping pass (`COMPOSITOR_UNIVERSAL_ROUTING_SCOPING.md`) sorted the ~18 in-scene blend materials into four routing categories — A: quad + OT-depth (tile overlays, tile cursor semi, `crystal_sprite`, callback grids/rings), B: arbitrary mesh (`shadow_blob`, TrailProjectile ribbons, `trap_charge_line`), C: depth-OFF overlays (C1 formation orb/box; C2 title cards), D: CPU-clamped full-screen screen tints — with routing cost set by geometry/placement/overshoot, and only ADD (1,3) / SUB (2) forcing the Mobile UNORM clamp (MIX mode 0 never overshoots, so pure alpha-blend materials are Forward+-safe). The 2026-07-31 DEMI2 fold audit oracle-verified the fold's color model: the additive fold is a pure per-channel scalar multiply (raw texel × grayscale COLOR modulate × scalar psx_brightness) and hence color-neutral by construction — the suspected gamma-space bug is absent for additive particles, and the `pow(psx_gamma)` branch, which had been dead because `EngineFoldCompositor` forced `srgb_to_linear=false`, is now structurally removed from the whole fold family (`effect_fold_add/sub/mix`, `cursor_fold`, `formation_orb_rim_fold`) under a new `check_no_pow_in_fold.py` guard with an empty allow-list, while the in-scene linear path (`effect_particle_opaque`, `probe_shaders`) keeps its legitimate pow round-trip; the residual oracle-vs-port particle differences trace to camera framing (~0.7×) and a ~6/255-per-channel bluer SHP palette decode, not to the fold.
