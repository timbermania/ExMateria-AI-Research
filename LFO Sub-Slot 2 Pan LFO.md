# LFO Sub-Slot 2 Pan LFO

FFT's mode-2 (pan-LFO) sub-slot, and the `protect_no_music` vol_inputs deficit that exposed it: an active mode-2 sub-slot fires on every fired-cadence tick, stepping the pan-LFO accumulator into chan+0x8a and co-arming `CHAN1_VOL_PRESTAGE` (chan_word_1 bit 0x100) on the same commit path as mode 1's chan+0x88 writer — so a single active mode-2 sub-slot alone re-arms the vol prestage every tick. On `protect_no_music` voice 21 (ch1) carries an active mode-2 sub-slot on PCSX (chan_8a ramping on 161/167 vol_inputs rows) although neither ch0 nor ch1 bytecode contains any documented LFO-arm opcode (0xD8/0xD9/0xE5/0xED) and 0xEC/0xEF contribute exactly 2 prestage arms; the arming source is unresolved (top candidate: Note handler implicit arm at PC 0x80015458). The missing per-tick co-arm is exactly 91 `vol_inputs` rows on the porta-active ticks of the dt=96 Note hold, and shows up mix-level as a phase-interference fingerprint (full_mix cos_dist 0.090 → 0.155 post-6-opcode-fix). Godot's mirror implements the mode-2 loop but defaults all four sub-slot modes to 0 (FFT pre-seeds [0,1,2,0]), arms sub-slot 2 only from the documented opcodes, and advances LFO state on voiced channels only where PCSX walks all 8. The 2026-05-17 reraise voice_19 doc (`VOICE_19_RMS_CHAN_8A_PAN_LFO_DIVERGENCE`) pins reraise's top `rms_spec_err` (voice_19, 0.0338) as the silent-driver pan-LFO class: PCSX runs mode-2 on all 4 reraise channels with the 3 silent drivers' sub-slot 2 pre-armed in the savestate (no 0xED/0xEC mode-2 dispatch anywhere in the spell), Godot had only the audible channel's mode-2 active, so the silent drivers' static last-write-wins L/R volume commits held the shared SPU voice's pan near-constant where PCSX's LFO-swept values slowly sweep it — `chan_8a` the sole diverging vol-formula input (240/592 rows) — and smd-player's `_apply_lfo_state_seed` now replays the savestate-pre-armed sub-slot state onto the silent drivers (the doc's §7.1 port).
