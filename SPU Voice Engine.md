# SPU Voice Engine

The shared SCUS SPU voice engine behind all FFT sound playback: a small set of driver primitives (trigger voices, per-handle key-off, per-voice set-volume) that every SFX path — system SFX, ambient `{6B}` bg sounds, and the feds/SMD effect sounds — funnels into, gated by a single audio-enable flag. The `{6B}` BG Sound investigation (2026-07) established the full static + dynamic picture of these primitives on live hardware, and the Godot reimplementation mirrors the volume path exactly (`vol << 8`). The 2026-04 MUSIC_41 synth-accuracy work (software SPU synth vs PCSX-Redux capture) pinned down the voice-level details: static sequential track-to-voice allocation, the `FUN_80017118` volume chain, ADSR sustain-direction bit and floor behaviour, and the SPU's Gaussian/ADPCM sample pipeline. The 2026-06 effect_sound folder README records the authoritative voice-space split: music owns SPU voices 0–15, effect SFX own voices 16–23. The 2026-05-12 audio-parity final-state doc (cure_no_music) closed the per-voice register layer: all of FFT's per-voice SPU register writes are bit-exact paired against Godot across 10 probe families, and a side-by-side C++ read confirmed Godot's native SPU mixer matches PCSX-Redux's implementation for ADPCM init/coefficients/loop flags, the ADSR attack/decay curves, the mix constants (/1023, /0x4000), and pitch→sinc (<< 4). The residual audio divergence lives in per-sample pitch modulation (see [[Effect Sound Audio Divergence]]). The 2026-05-12 next-steps probe doc (`AUDIO_PARITY_NEXT_STEPS`) adds the per-slot walker flag word — `slot+0x4` in the 24-slot pool walked at 0x160 stride by `FUN_80014590`, bits 0x01/0x02/0x04/0x08/0x40/0x80 scheduling the vol/sweep/pitch/sample-addr/ADSR2-high/ADSR2-low SPU fan-outs, 0x1FF-armed via the AC-dispatch path, set per-Note at PC 0x80015434, cleared at the walker tail 0x800147C0. The 2026-05-16 post-walker-flag-fix doc (`AUDIO_PARITY_NEXT_STEPS_V2`) adds the KOFF-prep constant-6 release-rate force (per-tick at PC 0x800152C0, vs the Note handler's pass-through at 0x80015438), the ADSR2_LOW SPU commit site (`FUN_8001BAB8`, PC `0x8001BAF8`, voice base `0x1F801C00` + 0x10 stride), the ADSR1 bit-range split across its three helpers, and the init-seed-only firing of ADSR1 and vol-sweep on `cure_no_music`. The 2026-05-13 CAUSE_A_PRESTAGE_TIMING doc re-attributes the 0x1FF arm to the 0xAC AC opcode's `Hyp_instrument_data_loader` (store at PC `0x80017088`, post-`FIRST_OPCODE_FIRED`) rather than an unconditional play_sound init seed, and maps the per-bit writer PCs on `cure_4`. The 2026-05-14 cure_4 Ch 2 investigation pinned the slot allocator's default seed (new slots start at `instrument_idx = 0`, which the AC data loader resolves to WAVESET inst[1] via the +1 rule — the instrument a Note-before-Instrument voice keys on with), and confirmed that on a noise voice the mix frame sources its sample from the noise generator, not SPU RAM. The 2026-05-14 pitch-default doc (`CURE_4_CH2_VOICE_18_PITCH_DEFAULT_INVESTIGATION`) closed the voice-18 pitch residual: FFT's slot-bind fan-out (`FUN_80014278` → `FUN_800144D0` → `FUN_8001B628` `spu_write_voice_pitch`) actively writes the bound voice's pitch register to `note_to_pitch(60, fine_tune)` (4078 on voice 18) before any opcode runs — an allocator default, not savestate residue — and Godot mirrors it by seeding `channel.bmidi_baseline_byte = 60` in `_bind_slot` for every slot. The 2026-05-19 cure_4_v18 batched-mixer plan adds the mix-loop level: PCSX's 1 ms mix entry is outer-voice/inner-sample with `NSSIZE = 45` and a `NoiseClock()` per active voice per sample position (off voices skip without advancing the LFSR), and at noise clock 43 the SPU LFSR shifts roughly once per 32 calls — Godot's pre-refactor native mixer was the transpose of that nesting (pinned cure_4 voice 18 at cos_dist ~0.13), and its batched outer-voice/inner-sample mirror has since landed in `fft_render_mix_batch`. The 2026-05-19 cure_4_v18 fix summary adds the routing and seed layer: FFT's entity-walk writer (FUN_8001_4F58 → 0x8001B070) re-asserts the savestate-restored SPUCNT (0x1F801D94/D96) noise/fmod/reverb bits every IRQ, the noise LFSR must be seeded from the capture anchor rather than the savestate value, and the LFSR freezes entirely while all voices are off. The 2026-05-18 death V21 doc pinned the public play_sound entry chain: gate `0x80012518`, public entry `0x80012520`, `Hyp_play_sound_variant_b` at `0x80012560` (calls `FUN_80013B20` only when `DAT_80032a54 & 0x1000`), and `FUN_80013B20` setting `chan_word_0 = 0x409` at PC `0x80013CD0`. A 2026-05-03 OPEN_QUESTIONS re-read corrects that entry attribution: per the Ghidra dump `0x80012520` falls inside the 72-byte gate `FUN_80012518` (0x80012518–0x80012560) — play_sound's entry is `0x800125A8`, with the audio-enable gate reference (`probe_play_sound_call` @ `0x800125C0`) inside it. The 2026-05-19 residue/noise-init doc adds the KEYON-state view: the LFSR state at the moment of each KEY-ON determines the noise content, so voice 18's late segment stayed uncorrelated under any constant shift until the KEYONs were aligned at the same absolute sample via residue-voice seeding (see [[Savestate Residue Voice]]). The 2026-05-19 walker-miss investigation corrects the 0x1FF attribution: exactly three ROM sites OR 0x1FF into `walker_flag_word` — 0x800154B8 (note-KON check), 0x80015E10 (opcode 0xAD), and `Hyp_instrument_data_loader` at 0x8001707C gated on `chan_word_0 & 0xC` — and the loader's immediate arm drives cure_4's cad-495 full re-init of voices 18+19 (see [[Cure 4 Audio Parity]]). The 2026-05-19 disillusionment_3 gate-deficit doc (`DISILLUSIONMENT_CHAN_WORD_0_GATE_DEFICIT`) adds the per-channel tick layer: the full `chan_word_0` state-bit table (0x001 slot-allocator low marker, 0x008 HAS_TONES, 0x080 NOTE_FIRED, 0x100 PITCH_REQ, 0x200 VOL_PENDING, 0x400 KON_ARM, 0x800 SLUR_PENDING, 0x1000 LAST_NOTE_FLAG, per `slot_state.gd`'s `CHAN0_*`), the per-entity channel walk (each entity walks entity+0xB8 + i×0x160 for channel_count channels — 8 on the audible primary, 2 per silent-driver entity — under the slot+0x10 pass gate at `0x80014BC4`), and the 488-row `disillusionment_3_no_music` gate deficit at `0x800151A0` (PCSX passes 2428/4376 vs Godot 1940/4648) — the gap is the 4 silent-driver channels FFT ticks every IRQ from savestate-resident state that Godot does not instantiate as dispatcher-bound channels (a modeling gap still open as of 2026-08-20). The 2026-05-16 ENTITY_ACC_SAVESTATE port-plan doc verified the entity-list layer against SCUS disassembly: the `DAT_80032A50`-rooted linked list with zero-terminated slot+0x00 next-pointers, the ~0xB8-byte entity struct field map with read-site PCs, the `FUN_800137d8` fresh-allocation inits (entity_acc 0x10000, budget 0x6600, subcounter 1, wrap_reset 0x30/slot+0x15), and the catchup arithmetic (outer `entity_acc -= entity_budget` at 0x80014CB8, +0x10000 sub-loop fires while entity_acc < 0, subcounter reloaded from slot+0x3a on wrap) — the arithmetic already mirrored bit-exactly in smd-player's `entity_state.gd` (`apply_outer_decrement`/`apply_sub_loop_fire`, validated by the `probe_per_entity_iter`/`probe_per_entity_pass` pairs) — and established that PCSX-Redux .sstate embeds a full 8 MiB RAM dump at 0x80000000, so the whole entity list can be lifted statically from a savestate with no PCSX round-trip (Phase 0 verified across 6 sstate captures by the 2026-05-16 verification doc — see [[Effect Entity Savestate]]). The 2026-05-24 ENV_VOL_ARCHITECTURAL_GATING doc (whose headline conclusion it marks wrong) records that Godot's shared SPU core already implements the non-loop ADPCM stop-sign voice-off — `stop_after_block` set at block end, `on = false` on the next decode, `envelope_vol = 0` on `!voice.on` — mirroring PCSX-Redux's start=-1 turn-off plus env zeroing, so the 'Godot lacks ADPCM stop-flag handling' root-cause candidate for the env_vol divergence was refuted by code review and the env_vol root cause remains open. The 2026-05-17 FMod-generalization doc (`FMOD_GENERALIZATION_PLAN`) closes the FMod routing picture: `FUN_8001_4F58`'s per-IRQ FMon mask builder is a gate-gated (s16 `entity[+0x10]` < 0, bit 0 splitting force-on vs normal) OR-accumulation of `entity[+0x68]`, combined with the running-state mask `DAT_80032A0C` and written as a SET+CLEAR pair to 0x1F801D90/92 (actual stores at 0x80019C8C/0x80019D60, computed base — invisible to literal-offset grep), and the mask's source is the SMD opcode pair 0xB2/0xB3 (handlers 0x80015ED8/0x80015F18) with the target-voice fields pre-staged at play_sound slot-bind time — smd-player now handles 0xB2/0xB3 bytecode-driven (`fmod_pending` → `flush_tick` → `set_voice_fmod` pair arm, reraise voice_21 cos_dist 0.0008), replacing the per-session hardcoded FMod table, with the SPU-state snapshot (`--spu-initial-state`) kept only as a diagnostic fallback.
