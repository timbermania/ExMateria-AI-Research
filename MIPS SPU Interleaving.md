# MIPS SPU Interleaving

On real PSX the SPU is a separate ASIC that mixes audio at 44.1 kHz continuously, asynchronously to MIPS: it does not pause while MIPS runs the 240 Hz RCnt2 IRQ handler, and an SPU register write (KON/KOFF, noise, pitch) takes effect for the very next sample the SPU processes — so during one IRQ window some samples mix with "pre-IRQ-write" state and some with "post-IRQ-write" state. FFT's `spu_updater_tick` places the walker fan-out early in the IRQ (0x800149F0) and the KOFF/KON commits late (0x80014EEC), so on hardware and in PCSX-Redux most of the cadence mixes with the walker's new register state while only the last few samples mix with the new KOFF/KON state — on `cure_4` v18 the `probe_envelope_tail` split measures ~259 samples sustain + ~27 samples release out of a 286-sample cadence. Godot's effect-sound render loop does not model this: it serializes the full per-IRQ dispatch (including the KOFF flush) before a single whole-cadence mix call, so on cure_4 v18 the voice's release reaches zero within one cadence and the audible release tail before the silence is missing (2026-05-19/20); the split-mix refactor proposed in `PCSX_MIPS_SPU_INTERLEAVING_REFACTOR.md` (pre-dispatch mix chunk + ~32-sample post-dispatch tail, constant `POST_DISPATCH_TAIL_SAMPLES`) was not started at the doc date — a 2026-08-20 probe found `POST_DISPATCH_TAIL_SAMPLES` absent from the smd-player and godot-learning code trees. The 2026-05-24 lfo_handler probe plan doc pins the mid-IRQ order: `smd_interpreter_tick` dispatch (0x8001536C) runs before `per_channel_tick`'s pitch work (chan+0x88 clear 0x800151BC, portamento advance 0x80015234), which runs before `lfo_handler_tick` (0x800174A4–0x800175F4) — so the probe BP at 0x800174C8 sees post-dispatch state. The 2026-05-17 WALKER_TICK_PRE_CADENCE_BUMP_DEFICIT doc pins the cadence-stamping contract — the `cadence_source` BP fires at the `FUN_800149DC` prolog, before both the walker's `jal` (0x800149F0) and the KEYON commit's `jal` (0x80014A10), so the walker's fan-out probes and the KEYON commit both stamp the same IRQ — and records the Godot pre-fix skew (the walker pass read the pre-bump cadence, stamping N−1 and gating out the first post-anchor pass entirely), closed by extracting the bump into `tick_irq_start`, called before the walker; it also establishes that the walker's probe gate sits above the unconditional SPU register writes, so the skew was trace-fidelity only with zero audio impact.
