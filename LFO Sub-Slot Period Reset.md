# LFO Sub-Slot Period Reset

FFT's per_channel_tick (FUN_8001517C) contains a per-tick LFO sub-slot period reset (PC 0x800157AC..0x80015804) gated by s4, which is set only when a Note dispatches with CHAN0_KON_ARM already armed (PC 0x80015488). It snaps every active first-segment sub-slot to a clean baseline (acc = 0, countdown = 1, dir = 3, `chan_word_0 |= 0x100`) so the LFO swap resumes at +step_source instead of drifting through the `(dir | 0x4) ^ 0x8` toggle. Godot lacked the reset until 2026-05-16: on protect_no_music the pan-LFO (sub-slot 2, chan_8a) sign-flipped, flipping the pan and swapping vol_l/vol_r; the fix (originally `_apply_lfo_period_reset` in dispatcher.gd, later refactored to `runtime/shared/per_tick/lfo_period_reset.gd`, which also models the delay/depth reloads) took all three vol probes from FAIL to OK. The 2026-05-17 probe-deficit doc pins the reset's `chan_word_0 |= 0x100` as the `CHAN0_PITCH_REQ` prestage trigger read by FUN_80017118 at PC 0x800171B8 and propagated to the per-voice walker as `walker_flag_word |= 0x1` (distinct from `CHAN1_VOL_PRESTAGE` on chan_word_1), and the 3-sub-slot walk count (a2 = 3 at PC 0x80015714 vs Godot's 4-slot loop, slot 3 inert by default). It also pins an open probe-visibility gap: the Godot `vol_prestage_lfo` emit still fires only at 0xD9 dispatch, so reraise_no_music pairs 1 Godot row against 32 PCSX rows even though the state snap itself is correct.
