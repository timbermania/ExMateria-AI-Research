# TRAP Charge Particle System

FFT's in-memory TRAP charge-effect particle system renders VFX for abilities that have no E###.BIN file: the charge VFX init in FUN_801a15b4 routes Charge+X abilities (IDs 406–413) through DAT_801b84dc to g_charge_effect_handlers[6] — handler 6 at 0x801b284c, a 3-state machine that spawns SCATTER-mode particles from the 46-byte config 10 at 0x801b8730 (fixed inward speed 1840, spawn point 18 units above the caster, downward gravity 0x1000) and runs the shared TRAP physics pipeline every tick until a fade_counter XOR-1 termination trick signals DONE; the same routing table maps SEQ-assigned anim_type 0x0D to handler 13 at 0x801b2d28, which spawns a rising outward burst from config 5 at 0x801b864a using an animated pos_scatter_y (−8 to −50 over 15 frames) and negative SCATTER speed. Handler 15 at 0x801b2e68 (SEQ-assigned anim_type 0x0C, config 4 at 0x801b861C) spawns exactly two zero-velocity SCATTER particles that sink under gravity-only and tracks them in an external 8-byte structure at DAT_801bc0e0 rather than the charge-effect slot. This note is a disassembly-derived reference for handlers 6, 13, 8, 9, 15, 17, and 19 covering routing, slot layout, config fields, spawn checks, CLUT computation, SCATTER velocity, the per-tick physics pipeline, lifetime management, and termination. Handler 17 (SEQ-assigned anim_type 0x0B, config 3) adds the first element-dependent runtime CLUT selection (DAT_801b88dc) and a direct-particle-management architecture on fixed global storage. Handler 19 (SEQ-assigned anim_type 0x13, config 15 at 0x801b8816) is the only charge handler with positive weight (+176/+192), which reinforces gravity (net 4272–4288/tick downward) and produces fast-falling particles that shoot straight up at fixed 180° with zero velocity spread (speed 2480–2512, 48-frame spawn window, fixed 12–16 frame lifetime).
