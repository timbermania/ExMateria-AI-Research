# March Opcode

Event opcode `{80}` March (Gariland's scenario-10 "Magic City" opener) is closed RE and ported: it does NOT start a walk — it re-applies each addressed unit's status-default natural animation (selector `FUN_80082eec @ 0x80082EEC`), releasing a cinematic-held pose back to the combat-idle "march in place" the unit has had since placement (construction `evtchr_unit_clut_writer @ 0x80087A28` reaches the same selector; refresh `FUN_80068d08 @ 0x80068D08` re-derives the anim from status words `+0x140/+0x144` every frame). Handler chain: `event_scenario_interpreter @ 0x80143BD8` (`opcode == 0x80`) → `FUN_80149490` → per-member `FUN_8008be54` → `FUN_80082eec`, then `event_fiber_yield_n(Time)` — `Time` is a per-unit stagger, `0` = lockstep (81 % of the 177-instance corpus). Gariland's March addresses a SINGLE `0x80` (slot 0, the PC20 speaker frozen by PC8 `{11}` Unit Anim). The port reproduces this end-to-end: spawn-into-combat-idle via `Unit.scenario_spawn_facing`, selector-aware release (`_op_march` → `ScenarioApply.march` → `ScenarioWorld.release_to_combat_idle`), reset re-armed through the resolver — `NavigatorGarilandVictoryTest` 14/0 (`March release 0x80`); per-unit `Time` stagger is decoded but not yet applied (scenarios 17/18/31/34 are the follow-up).
