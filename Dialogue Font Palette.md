# Dialogue Font Palette

The `{10}` Display Message font-palette mechanism, settled by static + dynamic analysis (2026-06-27): the only palette input is the `{Color NN}` string opcode `0xE3` — the handler's message walk latches it into `DAT_8016dae2` and passes it to the 2bpp→4bpp glyph rasterizer `FUN_8014bd88 @ 0x8014BD88`, where `final_index = glyph_pixel(1..3) + {Color NN}` is an additive offset into a 16-color dialog CLUT (`{Color 00}` default = slots 1–3 body, `{Color 08}` = slots 9–11 speaker name). Box type (`Dialog & 0x70`) drives box geometry/anchoring only and never touches the glyph CLUT. Which 16-color row a glyph actually samples is decided by the primitive's CLUT id, and all 22 FRAME.BIN palettes are resident in VRAM simultaneously (pal 0–15 at X=960 rows 496–511, pal 16–21 at X=976 rows 506–511): the chapel prayer (`Dialog=0x09`) carries CLUT id `0x7cbc` = VRAM (960,498) = FRAME pal 2 (off-white ramp) while the boxed dialog's glyphs carry `0x7c3c` = VRAM (960,496) = FRAME pal 0 (dark body (49,41,32), red speaker (106,41,16)) — the box path never takes the conditional `0x7cbc` store @ `0x80130FFC`, and the prayer renders through a separate pre-rasterized path that skips the rasterizer + `GsLoadImage` upload, so box body ≠ prayer body. `godot-learning` implements the box with a 3-level nearest-neighbor CUSTOM shader remap to the dumped CLUT (`DialogueBox` + `ui_font_char.gdshader`) and the prayer/menu text with the baked off-white atlas (FRAME pal 2). The `UIChar` glyph shader tints by multiplying atlas colour × `font_color` (darken-only; the prayer overlay's white `_container.modulate` is the atlas-native reference), and the baked comma glyph renders as a question mark.

## Points

- **String opcode `0xE3` (`{Color NN}`) is the ONLY palette input to the dialog font: the `FUN_801308c0` message-string walk writes `local_d4` (default 0) solely from `0xE3`, latches it to `DAT_8016dae2`, and passes it as `param_4` to the 2bpp→4bpp glyph rasterizer `FUN_8014bd88 @ 0x8014BD88`, which computes `final_4bpp_index = glyph_2bpp_pixel(1..3) + {Color NN}` — an additive offset into a single 16-color dialog CLUT, where `{Color 00}` (default) uses slots 1–3 (body ramp) and `{Color 08}` uses slots 9–11 (speaker-name ramp); box type (`Dialog & 0x70`) drives box geometry/anchoring only and never touches the glyph CLUT (statically proven).** — `[S·D·R] 3/3`

  - D: D1/D2 cross-checks on `orbonne_prayer_mid_dialog.sstate` (2026-06-27) — the D1 CLUT dump pins slots 1–3 / 9–11 as the body / speaker ramps and the D2 on-screen read confirms the `{Color 00}` body and `{Color 08}` speaker land in different ramps

- **Char-to-atlas-cell mapping must be derived from `psx_charmap.json`, not hand-rolled ASCII: single-byte `0x40..0x59` are HIRAGANA in the 2200-glyph BATTLE.BIN font (`0x41`='い', `0x43`='う', `0x47`='お'), so a hand-rolled ASCII punctuation block misroutes glyphs; single-byte chars resolve directly (`.` = `0x5F` @ atlas (310,14), `"` = `0x91` @ (170,28)), and the full-width punctuation the chapel prayer actually uses — `D9 C0` `"`, `DA 74` `,`, `D9 B6` `.` (hex-dumped at offset 2297 of `cinematic_event_chunk_0x8004A6BC.bin`; no single-byte ',' in the JP charmap) — are 2-byte sequences that map to font indices 256..2199 under the FFTPatcher `BuildVersion3Charmap` ordering (index i≥0xD0 to key `0xD100 + 0x100·floor((i−0xD0)/0xD0) + (i−0xD0) mod 0xD0`; e.g. `0xDA74` ',' = index 2196 @ (200,476)), with the loader's last-wins dict making multi-byte glyphs win char-keyed lookups.** — `[S·R] 2/3`
  - S: `godot-learning/tools/data/psx_charmap.json` cross-checked against BATTLE.BIN's 2200-cell font + chunk hexdump (round-5, 2026-06-29)
  - R: `godot-learning/tools/parse_fft_font.py` (derives `FFT_CHAR_MAP` from `psx_charmap.json` at parse time; `BuildVersion3Charmap` port) re-bakes `godot-learning/assets/fonts/font_meta.json` (char-to-cell map incl. multi-byte byte-sequence keys) consumed by `DialogueOverlay.gd` — validated by `DialogueOverlayTest.gd`
  - src: `research/working_documents/scenario_1_captures/display_message_overlay_decode.md`
- **The `UIChar` glyph shader multiplies the atlas colour by `font_color` (`final_color = color.rgb * font_color.rgb`), so a sub-white tint can only darken below the atlas-native colour, never brighten it — the prayer overlay's white `_container.modulate = Color(1,1,1,1)` renders the atlas as-is (cream `(248,240,208)`), the untinted reference the boxed `DialogueBox` must match, and the box's one-off Phase-3 body dim (`body_color = Color(0.60,0.57,0.50)` set per body char in `_apply_palette_runs`) read dimmer than the overlay for exactly this reason** — `[R] 1/3`
  - R: `godot-learning/src/ui3/shaders/ui_font_char.gdshader` L120 (`color.rgb * font_color.rgb`) + `src/ui3/elements/UIChar.gd` `font_color` export (L78) + `src/scenarios/DialogueOverlay.gd` `_container.modulate = Color(1,1,1,1)` (L185/L485) — validated by `godot-learning/tests/DialogueOverlayTest.gd::_test_color_and_newline_drain_free` (atlas-native overlay colour; no dedicated dim-regression test)
  - src: `research/working_documents/scenario_1_captures/handoff_boxed_dialog_polish.md`
- **Comma renders as a question mark in dialog text ("moment," → "moment?"): a baked-font glyph-mapping quirk in the shared charmap (`char_to_index`: `,` → 2196, a distinct cell from `?` → 64; both resolved through `font_meta.json`), affecting the prayer overlay and the boxed `DialogueBox` alike — not a box bug** — `[R] 1/3`
