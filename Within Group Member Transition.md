# Within Group Member Transition

How FFT jump-cuts between the *members* of one scenario battle group (Gariland 10 → mid-combat chat 11 → victory 12): driven not by the ATTACK.OUT scenario table but by the group's BattleConditionals set (`{0x0019} Run Scenario N`) evaluated during combat. The crux question — what scene state a member inherits when it fires mid-combat — is settled for the map palette: combat does NOT reset it (H-KEEP, live-verified 2026-07-11), so Godot's palette preservation across members is faithful; the observed "Gariland member 11 renders blue" bug was a Godot-side `{66}` commit-timing defect, root-caused and fixed 2026-07-11. The PSX BC evaluator closed statically (2026-08-22: `bc_evaluate 0x801425B0` / `bc_predicate 0x80142694`, a 22-case predicate ladder) and then dynamically the same day (Exp D′): the jump-cut is raised by the battle state machine's kind-8 event dispatch — not the scenario interpreter's own re-evaluation — through a probe → per-scenario gate → commit protocol; `Victory` means the enemy is wiped with at least one player unit standing (`b[0x1BA] & 0x30 == 0` = player's side); the raiser and the interpreter each refuse the game-over scenario band 400..425. Still open: whether a member *replaces* or *overlays* the live battle.
