# Wait For Instruction Opcode

`{E5} Wait For Instruction(Task=N)` is the FFT event VM's generic cooperative-task barrier: one yield+poll loop (the `0xE5` case at `0x80145964` in scenario interpreter `FUN_80143bd8`) that yields a frame via `FUN_8014ca80` and rescans the 16-slot cooperative-task array (`*0x80165f98` = `0x8016986c`, stride `0x400`), releasing when no active slot (`+0x48`) has kind key (`+0x4c`) equal to `Task=N`. `Task` is the cooperative-task *kind* enum (1=dialog, 4=camera, 8=nested block, 52=EVTCHR load, 54=dark screen, 61=screen/effect; 56 has no store site), not an opcode number or slot index, and `0xE5` is the same machine as the dedicated Wait-family barriers, which hard-code their kind and add a `+0x50` unit filter. Static decode (BATTLE.BIN) plus live PCSX probes on the Orbonne prayer beat — including interpreter-state sampling that re-attributed the 255-frame hold to the Task=1 dialog barrier, not Task=4 — established the mechanism; Godot's `ScenarioVM` mirrors it with a kind→liveness registry (`_register_task_kinds`) feeding a generic `wait_until` poll, and the prayer untint lands within +8f of PSX.

## Points

- **`{E5} Wait For Instruction(Task=N)` is a generic cooperative-task barrier, not the boxed-dialog advance gate: the handler is the `0xE5` case at `0x80145964` in scenario interpreter `FUN_80143bd8`, and its poll loop (`0x80145974..0x801459c4`) yields one frame via `FUN_8014ca80` then rescans slots 1..15 of the 16-slot task array (`*0x80165f98` = `0x8016986c`, stride `0x400`), re-yielding while any active slot (`+0x48 != 0`) has kind key (`+0x4c`) equal to the 16-bit `Task` operand, and releasing when no slot matches — so a `Task` that never matches still costs exactly one yielded frame.** — `[S·D·R] 3/3`

- **Action opcodes NEVER halt the main thread: `0x10` Display Message spawns the typewriter as a separate fiber via `FUN_8014c8a0(slot, FUN_801308c0)` (stores the entry at `slot+0x44` and sets active `slot+0x48 = 1`) and falls through to the next opcode in the SAME frame with no yield — the typewriter's `FUN_8014ca80` yields live in the fiber, not the main thread — and `0x11` Unit Anim is even purer fire-and-forget, running inline and allocating no slot, so a Wait placed after a Unit Anim waits on a *different* concurrent task (kind 4 camera or kind 8 sub-block), never on the anim itself; halts may therefore live only on Wait-family opcodes.** — `[S·D·R] 3/3`
